# 收尾介面真人試用腳本（約 10 分鐘）

版本：2026-11-06 Merge／Rebase 簡化版。尚未執行真人試用，不以面板自動測試代替。

目的：確認使用者能辨識目前工作、選擇合適策略，並理解下一個按鈕的結果。找一位 Git 新手與一位熟手各自試用，主持人只觀察、不提示。

## 準備

僅在已授權的隔離測試儲存庫準備來源 worktree 與 main，讓雙方各有提交，來源再留一個未提交檔案。關閉雙方終端與 AI，開啟 GitFlow Hub。以下任務停在確認頁；只有另獲准的隔離 fixture 才按最終確認。

## 任務

| # | 跟受試者說的話 | 算成功的條件 |
| --- | --- | --- |
| 1 | 「你做完了，要保留原有提交，把成果合回 main。請準備收尾。」 | 找到目前工作並核對來源路徑，選 Merge，按預覽，能說出來源 → 目標，以及分歧時會新增 M。 |
| 2 | 「希望把你的提交接在 main 的新進度後面。請調整選擇。」 | 返回修改、選 Rebase，能說出提交編號可能改變，工具還會快轉目標；不把 Rebase 當成合成一個提交。 |
| 3 | 「請把來源提交整理成一個，但保留工作資料夾。」 | 在其他選項開啟 Squash，移除資料夾保持未勾；返回修改仍保留選擇，能辨識目前是 Squash + Merge 或 Rebase。 |
| 4 | 「還有一個檔案沒提交。確認後會處理哪些檔案？若要分批提交該去哪裡？」 | 能看到全部變更提交提醒、展開檔名，知道包含已暫存、未暫存與新增檔案，分批提交須先去 Orca 版本控制。 |
| 5 | 「如果要在合回後移除工作資料夾，會移除哪裡？如果預覽說有衝突，下一步是什麼？」 | 勾選清理後能指出確切路徑與分支保留；衝突時能返回修改或開啟來源處理，不在結果未知時直接重送。 |

## 紀錄與判定

每項記錄是否獨立完成、耗時、停頓超過 10 秒的位置及誤解用詞。最後請受試者用一句話說明 Merge 與 Rebase 的差別，並指出最終確認按鈕。

兩位受試者各至少完成 4 項，且來源／目標方向、全部檔案提交、歷史改寫與清理範圍沒有誤解，才判定本輪可用性通過。未達標時記錄卡點再調整。自動測試通過不代表真人、鍵盤或 VoiceOver 已通過。
