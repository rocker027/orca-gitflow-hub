# 收尾介面真人試用腳本（約 10 分鐘）

目的：確認不熟 Git 的人能不能自己完成收尾。找一位沒用過這個外掛、不熟 Git 的人操作，主持人只看不教。

## 準備（主持人，約 3 分鐘）

1. 在測試專案（例如 `orca-worktree-test`）用面板「開始新工作」建一個工作，改兩三個檔案，提交一次、留一個不提交。
2. 在 main 另外提交一次，讓 main 先前進。
3. 關掉這個工作和 main 的終端機與 AI 助手，打開 GitFlow Hub 面板。

## 任務（受試者自己完成，主持人不提示）

| # | 跟受試者說的話 | 算成功的條件 |
| --- | --- | --- |
| 1 | 「你做完了，請用最安全的方式把這個工作放回 main。」 | 不需要提示就按「完成這個工作」→「下一步：確認」→「確認，開始合併」，看到「完成了」，全程不用填完成說明 |
| 2 | 「主管要 main 只多一個提交，請完成另一個工作。」（主持人先準備第二個工作） | 選「合成一個提交」，並用第 2 題「接到最後面」或「改成讓 main 只多 1 個提交」完成；main 只多 1 個提交 |
| 3 | 「不確定會不會出問題，先問問 AI 再決定。」 | 展開「其他選項」，按「（可選）請 AI 評估合併風險」，看完同意說明後送出，能說出建議的風險等級 |
| 4 | （主持人先讓 main 和工作改同一行）「請完成這個工作。」 | 看到「需要處理」後能說出：main 沒有被改動、改動還在、下一步要找人協助 |

## 觀察與紀錄

每個任務記錄：是否完成、花多久、在哪裡停下來超過 10 秒、有沒有說出「這是什麼意思」、有沒有按錯。

做完問三題：

1. 哪一步最讓你猶豫？
2. 有沒有哪個字看不懂？
3. 如果明天自己做，你有信心嗎？（1–5 分）

## 判定

- 4 個任務中至少 3 個不需要提示就完成，而且沒有人因誤會而按錯，就算通過。
- 任何一題被卡住，記下停住的畫面與文字，回報後再調整。
